# 本地用户记忆与截图自动回答

日期：2026-11-11

## 目标

截图圈选后，用户可以在截图页面底部补充需求，再点击“确认”直接进入 AI 对话并发送，取消“AI 解题 / 讲知识点”的必选步骤。补充需求可留空。原“预览选区”按钮更名为“确认”，保留用户确认选区的操作。AI 根据选区、用户补充需求、当前对话和本地用户记忆判断任务与讲解深度。不同用户逐渐形成各自的回复偏好，不把某个人的英文翻译习惯写成所有人的固定规则。

保留当前对话记忆，并加入跨对话的简短用户记忆：回复风格、习惯、近期学习内容、此前接触的知识。所有持久化数据保存在本机。

## 已有实现

- SelectionOverlay 中，选区先预览，再点击两个 AI 动作之一；两个动作分别发送不同的隐藏首问。
- AiConversationView 新建时自动发送首问，恢复时带回历史；ConversationStore 保存完整历史、题图、草稿及未完成回答。
- AiWire 每次带上全部历史和原始选区图；AiClient 限制 40 条历史消息，界面另限制 10 万字符，没有摘要或跨对话记忆。
- 系统提示词和动作提示词可编辑，支持 Chat Completions、Gemini、Anthropic 三种协议。

## 方案比较与选择

1. 每次携带所有历史：实现简单，但不断增加费用和延迟，容易带入无关内容，不能满足简短记忆目标。
2. 本地结构化用户记忆 + 对话摘要：记忆易查看和删除、长度可控、不需要账号后端。采用此方案；用户已明确选择本地保存和自动提炼。
3. 云端账号与检索服务：可跨设备同步，但用户当前不需要，暂不实现。

以下具体策略是实现方建议，尚待用户审阅。

## 截图与回答流程

- 自由圈选、矩形选区完成并得到有效选区后，等待用户点击“确认”；此时仍可重画，不发送请求。原“预览选区”按钮更名为“确认”。
- 截图页面底部、确认按钮上方增加可选的多行输入框，提示“补充需求（可选），例如：翻译、解释原因”。不强制输入，不自动弹出键盘；圈选和重画时保留当前输入，关闭本次截图后丢弃未发送内容。软键盘出现时输入框和确认按钮可见，不改变选区的截图坐标映射。
- 点击“确认”后裁剪并直接打开对话，自动发送一次，不再等待预览页操作或选择“AI 解题 / 讲知识点”。无效选区、重绘过程、取消手势以及未点击确认时不得发请求；防止连续点击重复计费。
- 补充需求去除首尾空白后非空时，与选区图一起作为明确用户首问发送，并显示在对话中；留空时使用统一截图首问，继续隐藏自动首问。补充需求随首次请求和历史持久化，重试或配置缺失后继续时保持原文，不重复追加。明确需求优先于记忆偏好和自动任务判断，不把单次补充指令直接视为永久偏好。
- 移除必选的两个 AI 动作，保留选区确认步骤；分享等辅助能力迁到对话中的选区预览入口。原始屏幕全图不得上传。
- 配置缺失时进入模型设置；保存后自动继续该次请求一次，返回或取消设置不发送。
- 未填写补充需求时，统一首问表达“根据选区判断最有帮助的处理方式，直接给出结果和必要解释”，不固定要求逐句语法分析或完整解题教学。内容不清楚时只问必要的问题。
- 系统回答原则：按当前意图提供足够答案，简单问题简短回答，复杂问题保留必要推理与步骤，不使用固定冗长模板。个人记忆只用于适配，当前明确要求优先。
- 提示词设置改为系统提示词和统一截图首问；已有自定义系统提示词保留。旧解题/讲解提示词保留存储但不自动合并到新首问，避免继续携带单一任务指令。
- 历史对话保留原来的首问语义，不回写已有消息。

## 本地记忆结构与使用

- 独立的本地记忆存储，跨模型配置、跨对话使用；不等同于历史列表。
- 每条包含 id、类别、简短内容、适用范围、证据来源对话/用户消息、创建与更新时间，以及明确表述/反复推断的依据。
- 类别：回复偏好、学习习惯、近期学习主题、曾接触的知识。上限初定 40 条，每条不超过 160 字符，允许去重合并；近期学习主题按更新时间和关联度取用。
- 用户明确说出的偏好可以立即提炼；隐含偏好至少有两次不同用户消息支持。一次“简短些”优先作用于当前任务，除非用户说明是长期习惯。
- 截图原文、引用材料、模型自己的回答都不能当作用户偏好指令。截图主题可作为“接触过”的证据，不据此认定用户正在系统学习或已经掌握。
- “最近学习”“以前问过/接触过”和“已掌握”必须区分；掌握情况只记录用户明确自述，不凭回答正确或提问次数判断。
- 选择少量相关条目加入每次请求，初定最多 12 条、总计 1600 字符；通用回复偏好优先，学习主题与当前问题匹配。找不到相关项时不强行注入。
- 记忆作为带边界的参考资料使用，不赋予覆盖当前问题或系统规则的权限。三种请求协议均使用相同的选取逻辑。

## 自动提炼

- 成功完成一轮问答后，以新用户消息、必要的对话片段和已有记忆进行后台文本提炼。使用当前配置的模型及现有接口能力，不上传额外截图，不使用 API Key 等配置内容。
- 明确偏好可在该轮后提炼；普通学习内容每完成约 3 轮或对话收尾时合并提炼。按已处理消息位置去重，同一批消息不重复提炼；关闭窗口后任务仍可完成。
- 输出为受限结构化候选增删改操作，由本地代码校验、去重和原子写入，不允许模型任意修改文件或执行指令。
- 后台请求会产生额外 API 用量，在记忆设置中说明；失败不影响主回答，不自动无限重试，后续新消息可触发下一次处理。
- 首版只自动提炼启用后的新消息，不在升级时批量扫描全部历史。历史仍可查看和继续，继续后新消息可用于提炼。

## 当前对话摘要

- 磁盘保留完整历史，发送上下文采用“摘要 + 最近若干轮 + 当前问题 + 原始选区图”。
- 接近当前 40 条/10 万字符限制前，压缩较早消息为有界摘要，记录讨论主题、明确要求、已得结论和未解决问题，不把整个对话变成永久用户记忆。
- 摘要和覆盖到的消息位置随会话保存；成功后原子推进。摘要失败不删除历史，不发送超限请求，保留用户输入并允许重试摘要。
- 初定超过 24 条历史消息或 24000 字符时触发；保留最新 8 条消息并保持完整问答对，摘要不超过 3000 字符。单条过长时给出可恢复提示，不静默丢弃用户消息。
- 恢复历史、切换模型、停止与重试均不得重复推进摘要或记忆游标。

## 用户控制与生命周期

- 提供“记忆”入口，可查看、编辑、删除、清空，关闭自动提炼和关闭使用记忆。用户编辑条目标为明确偏好。
- 删除条目后旧证据不再使其复活；清空或关闭自动提炼期间，取消/作废已排队的候选写入，以存储版本校验阻止迟到请求恢复记忆。之后新的明确表述可以重新形成记忆。
- 删除某条历史时删除其关联的提炼证据；只由该会话支持且未经用户确认的记忆一并移除，其他独立证据支持的条目保留。
- 无账号、无云端数据库或设备同步。提炼及使用记忆时，必要文本仍会发送给用户配置的模型服务商；“本地保存”不表示在手机本地运行模型。

## 验证与范围

- 验证圈选完成但未确认时不发送，点击“确认”只触发一次请求，按钮不再显示“预览选区”；取消与无效选区不发送，设置返回恢复，旧历史与自定义系统提示词兼容。
- 验证补充需求留空或仅空白时仍正常自动判断；填写时三种协议均携带原文、在对话中显示，并在重画、配置返回、失败重试中保留；键盘不挡住输入与确认，不使选区裁剪偏移。
- 验证记忆跨会话读取、相关性筛选、明确要求优先、截图文字不成为偏好、未证实的学习状态不提升为掌握。
- 验证提炼失败不破坏主问答，编辑删除清空与后台请求并发时不会恢复被删除的内容。
- 验证长对话摘要后可继续、原始历史未丢失、摘要失败可恢复，三种协议都携带一致的上下文。
- 构建 Android 应用，使用已有自动化检查与可用模拟器验证核心流程；真实模型的回答质量需以实际样例评估，提示词无法保证每次意图判断正确。
- 暂不做云同步、向量数据库、整库历史回填、学习计划/练习生成或复杂画像推断。
